# 茶訊調查局：第一關改造方案

這份文件定義本次茶課手機網頁遊戲的第一關可玩原型，供實作與審查使用。第一關驗證「面對未知資訊時如何調查」的玩法；本階段不製作第 2–6 關、不接後端，也不發布。

## 一、現況與目標

### 現有產品

目前倉庫只有 README.md、單檔 index.html 與前端設計規範。遊戲使用 Tailwind CDN、內嵌 CSS 和 Vanilla JS，不需建置、登入或資料庫。畫面依序是開始、真假題、立即解釋、總分；10 道固定題目在開始時洗牌，不是從更大題庫抽樣。每題資料含繁中與英文的題目、解釋、來源，以及單一 isTrue 答案。每答對一題加 10 分；無返回修改、證據比較或不確定選項。README 以雙語、大字與高對比為現有能力。

保留紙色、黑色粗框、警示紅、查證綠、檔案／報紙感、字體氣質與免登入靜態網站架構。重整緊扣真假題的資料、狀態切換、單一總分與回饋文案。2026 年春季班版原樣保存在 `2026-spring/index.html`（線上網址為 `/tea-game/2026-spring/`），連同英文切換；新版首頁只做繁體中文第一關。

### 本次成功標準

學生掃 QR Code 後直接看到「第一案」，能獨立完成一次「讀訊息 → 記錄直覺 → 選行動 → 找要查的地方 → 比證據 → 修正判斷 → 看學習回饋」。過程讓玩家點出要查的句子、比較證據的用途和限制；不把內容改裝成另一套真假選擇題。手機上無橫向捲動、無必要的巢狀捲動，所有關鍵操作可觸控。

不設目標時長。學習效果（玩完後遇到新訊息會不會先問出處）另外找人試玩驗證，不做進原型。

### 六案總表

全系列暫定六案，真假混合，避免玩家學成「每則都是假的」、全部點過就拿分。每案教一招，結論不固定是「假」。題材一律不取自 2026 年春季班的 10 題，因兩屆學生有重疊，看過就知道答案。本階段只做第一案，下表只定題材與招式，文案等第一案試玩後再寫。

每案的計分寫在自己的情境資料裡：第二節「計分規則」只適用第一案；結論是「真的」的案，「應該是真的」得分最高。

六案的畫面、題目與選項完全相同，玩家無法從選項看出這案是真是假；各案只換訊息、提示、證據卡內容、得分與回饋：

- 題目文字、五個行動、三個最後判斷、四項分數名，六案一字不差。
- 每則訊息切成六句可點的句子：四句「要查」、兩句「不用查」，門檻一律找到三處。「要查」是訊息裡的具體說法與條件，真的案也有（如「隔一小時」「缺鐵的人」）。提示只說這句該查什麼、查到什麼，不先講結論。
- 點到「不用查」的句子不扣分，避免長輩受挫；防止「全部點一遍就過關」靠真假混合與最後判斷的計分。
- 每案都是 A、B、C 三張卡，按「跟其他資料對對看」才出現 D。
- 每案的結論都要落在三個最後判斷之一。第四案以「應該是假的」得分最高：訊息說的「不用節食就能甩油」研究沒測到，體脂也沒變。

## 二、第一關內容與畫面

### 情境訊息

轉傳訊息是教學模擬，不冒充真實群組截圖。訊息泡泡文案如下：

> 阿姨剛轉來，給大家參考一下🍵
>
> 前陣子看到一篇分享，說日本有醫學研究發現，每天喝三杯普洱茶，對清掉血管裡的油脂有幫助。連續喝 28 天，血管狀況甚至可能「年輕十歲」。
>
> 我朋友的醫師也說，平常喝茶對心血管不錯。家裡有長輩的可以留意一下；覺得有用也轉給親友看看❤️

訊息卡右上角標「轉傳訊息（教學模擬）」。案卷註記「這則訊息沒有附研究名字，也沒有連結。」在進入 CLUE_HUNT 時顯示在泡泡下方；不在初始閱讀與可信度評分前顯示，也不放進轉傳泡泡。文案保留少量可信線索與社交語氣，不使用過度荒謬的驚嘆號或虛構醫院名稱。

### 文案規則

玩家是 40–60 歲、在課堂上邊聽邊玩的叔叔阿姨。所有玩家看得到的字都照這幾條，內部 id 與四項英文欄位名不受此限：

- 用台灣日常說法，例如「上網查」「出處」「轉傳」；不用大陸用語或翻譯腔。
- 一句只講一件事，盡量不超過 20 字；不用專有名詞（觀察性研究、相關性、因果、校準、轉述來源），一律換成白話。
- 選項是 2–6 字的短詞，彼此對等，不附理由。任何一個選項都不能聽起來像標準答案，也不能聽起來像陷阱；「很可疑」「直接刪」「官方」這類帶評價的字不用。
- 標題與分數名同樣中性，不加「真的」「官方」「權威」這類暗示好壞的字。
- 標題、標籤用最短的常用詞（如「回顧」「查之前／查之後」），不自創口語片語。
- 驗收時請一位 50 歲以上的人朗讀全部文案，卡住、要想一下、或覺得「一看就知道該選哪個」的地方都要改。

### 狀態機

MESSAGE → INITIAL_BELIEF → ACTION → CLUE_HUNT → EVIDENCE → FINAL_VERDICT → REFLECTION → RESULT

- MESSAGE：顯示「第一案」、完整轉傳泡泡、「開始調查」。
- INITIAL_BELIEF：題目「這則訊息，你信幾分？」0–100 滑桿，兩端標示「完全不信／完全相信」。玩家必須操作滑桿才可儲存 initialBelief；不以預設 50 充當回答。
- ACTION：題目「看到這則訊息，你會先怎麼做？」五個選項見草稿。選後給一句結果；不真的對外轉發。任何選擇都能繼續調查。
- CLUE_HUNT：題目「哪幾句要查一下？點點看。」訊息中有四處要查（「日本有醫學研究」「朋友的醫師」「28 天」「年輕十歲」）和兩處不用查，六處外觀相同，點了才知道。messageSegments 是畫面文字的唯一來源，clues 只引用片段 ID，不另存一份可能漂移的觸發文字。每處就地打開一句提示並留下「要查」或「不用查」標記；找到任意三處要查的可繼續，第四處仍可查看。點到不用查的句子不扣分、不計入三處。重複點擊不重複得分。
- EVIDENCE：題目「這些資料，哪一份最能幫你判斷？」一開始只有 A、B、C 三張卡，正面只顯示標題，點開才看「內容／可以參考的地方／不夠的地方／原始連結」。C 背面有按鈕「跟其他資料對對看」，按了才出現 D。至少打開兩張後才能選，按對照後自動展開的 D 也算一張；選擇後可繼續。
- FINAL_VERDICT：題目「查完之後，你覺得這則訊息……」選「應該是真的／還不確定／應該是假的」，再主動設定 finalBelief（「現在你信幾分？」）。兩項齊備才提交。
- 證據卡與最後判斷的「選後那一句」不在選的當下顯示，到 REFLECTION 才出現，避免玩家每個點一遍、挑被肯定的那個；行動的選後那一句照常選了就顯示。
- REFLECTION：標題「回顧」，顯示「查之前 N 分 → 查之後 M 分」、玩家選的資料與判斷（各附選後那一句）、案件結論、「第一招：先問出處」。四個要查的地方見草稿；避免宣稱「茶完全無效」。
- RESULT：顯示「這一案的練習分數（僅供參考）」四項分數、每項一句依實際選擇生成的回饋（見草稿）和「再玩一次」。不要用「你比多少人強」之類無資料支持的評語。

EVIDENCE 的卡：A、B 為模擬素材，C 為真實觀察研究，D 是玩家從 C 出發、拿訊息去對照多份資料的結果（本遊戲明示整理）。D 由玩家的對照動作產生、不一開始擺出來，避免玩家學成「挑那張整理好的卡」；它直接對照「28 天清血管」的主張與證據缺口，是本關最適合的判斷依據，但須寫明它不是原始研究、也不證明茶無效。全文見下節。

### 情境資料草稿

以下即 scenarios[0] 的全部文案，實作直接取用；醫療表述已對照第三節來源，改動須同步回這裡。

**四項分數的畫面名**（id／畫面名）

- source／查來源
- evidence／看證據
- calibration／下判斷
- spread／轉不轉

**線索**（id／訊息原句／加分項／點開的提示；最後兩條是不用查的句子，不加分）

- study／日本有醫學研究／source：哪個研究？誰做的？都沒寫。沒有名字，就查不到。
- doctor／朋友的醫師／source：這是聽朋友說的。醫師只說喝茶不錯，沒說 28 天能清血管。
- days／28 天／evidence：28 天說得很具體，但幾個人試過？怎麼量的？都沒寫。
- young／年輕十歲／evidence：血管要怎麼量出「年輕十歲」？沒有說。講得越神奇，越要找出處。
- tea／平常喝茶對心血管不錯／無：這句說得很保守，沒講什麼神奇效果。
- family／家裡有長輩的可以留意一下／無：這句是關心，沒講到什麼事實。

**行動**（id／選項／選後那一句）

- forward／轉給家人：已轉出（模擬）。家人問你：是哪個研究？你答不出來。
- ignore／不理它：沒回，也沒轉。但沒查過，下次換個說法傳來，還是分不出真假。
- source／問是哪裡來的：對方說：我也是別人轉的，不知道原文在哪。
- search／上網查一下：查不到這個研究，只看到一堆一樣的轉貼。
- hold／先不決定：先不轉，繼續查查看。

**證據卡**（id／標題／來源類型／內容／可以參考的地方／不夠的地方／選後那一句）

- A／網路養生貼文／社群貼文（模擬）／「日本研究證實：每天三杯普洱茶，28 天血管年輕十歲！」／看得出這個說法在網路上傳得很廣／沒附研究，大家只是互相轉貼／很多人講一樣的話，不代表多了一份證據。
- B／醫師受訪畫面／影片截圖（模擬）／字幕：「平常多喝茶，對心血管有幫助。」／有醫師說喝茶不錯／找不到完整影片。沒提普洱茶，也沒提 28 天／只有一句話，看不到前後文，也沒講到 28 天清血管。
- C／醫學期刊研究／2017 年醫學期刊（真實）／追蹤很多人好幾年，常喝茶的人，得心臟病的比例稍微低一點。／這是真的研究，查得到／講的是平常喝茶，不是普洱茶喝 28 天。也沒量血管裡的油脂／這篇研究可靠，但它回答的是另一個問題。
- D／三份資料對照／本遊戲整理／我們把 C 這篇研究、食藥署的文章、美國心臟協會的資料放在一起看。沒有一份提到「普洱茶 28 天清血管」。／拿訊息的每一句去對，看有沒有資料說過／這是我們整理的，不是訊息講的那個研究；也不代表喝茶沒用／你拿訊息的每一句去對資料，這才是判斷的根據。

原始連結的畫面名稱：C「研究原文（英文）」；D 另加「食藥署的茶與健康文章（英文）」「美國心臟協會：血管健康（英文）」；A、B 顯示「沒有，這是模擬的資料」。

**最後的判斷**（id／選項／選後那一句）

- credible／應該是真的：沒有一份資料說過「28 天清血管」。喝茶不錯是真的，但那是另一回事。
- insufficient／還不確定：找不到出處，不代表一定是假的。查清楚之前，先不轉最保險。
- suspicious／應該是假的：找不到出處，確實要小心。不過找不到，不等於證明是假的。

**反思頁**

- 案件結論：印章「找不到出處」，內文「現有資料都沒說「28 天清血管、血管年輕十歲」。」
- 第一招：先問出處。
- 四個要查的地方：沒有研究名字，查不到／醫師的話是聽朋友說的／「28 天」沒說幾個人試過、怎麼量／「年輕十歲」沒說怎麼量。

**四項回饋**（依實際選擇取句）

- 查來源：首選「問是哪裡來的／上網查一下」時顯示「你一開始就先問出處，這是最重要的一步。」；其餘顯示「你後來有找到要查的地方。下次收到訊息，先問：這是哪裡來的？」
- 看證據：選 D 顯示「你拿訊息的每一句去對資料，看得很仔細。」；選 C 顯示「你選的研究很可靠，但它講的是另一件事。」；選 A 顯示「這份資料跟訊息講的一樣，但證明不了什麼。」；選 B 顯示「這份資料沒講到 28 天清血管，幫不了判斷。」
- 下判斷：選「還不確定」顯示「證據不夠，就先不下定論，這樣很好。」；選「應該是假的」顯示「保持警覺很好。不過找不到，不等於一定是假的。」；選「應該是真的」顯示「資料都對不上，這時候先別急著相信。」；首選「不理它」的，在後面加一句「不理之前先查一下，會更有把握。」不依滑桿變動幅度推斷玩家是否學會。
- 轉不轉：首選「轉給家人」時顯示「你一開始就轉出去了。下次先停一下，查了再轉。」；其餘依最後判斷：「還不確定」顯示「你沒有轉，這則訊息就停在你這裡。」；「應該是假的」顯示「你沒有轉。也可以提醒家人：這則找不到出處。」；「應該是真的」顯示「你還沒轉。轉之前，先確認那個研究在哪。」

### 計分規則

四項（顯示名見草稿）各以 50 起算、限制在 0–100，畫面標為「這一案的練習分數（僅供參考）」，不當作科學量表。分數由目前答案重新計算，不在點擊事件中累加；返回改答案、重複點擊與重玩都不能刷分。初始和最終可信度只用來觀察觀點更新，不因數值高低或改變幅度直接給分。

| 選證據 D／C／A 或 B | 0 | +20／+10／-10 | 0 | 0 |
| 最後選「還不確定」 | 0 | 0 | +20 | +20 |
| 最後選「應該是假的」 | 0 | 0 | +10 | +15 |
| 最後選「應該是真的」 | 0 | 0 | -20 | -10 |

證據 D 的較高分來自它直接對照「28 天清血管」這個具體主張及其證據缺口；C 是可靠研究但回答的是另一個較寬的問題。卡片回饋需解釋這個差別，不能只靠機構名稱判高低。

## 三、資料與技術

新版維持單檔 index.html 原型，將畫面、樣式、情境資料、純狀態邏輯分成清楚區段；不引入 React、建置流程或 API。資料採 scenarios 陣列，一關一物件，至少包含 id、title、sourceType、messageSegments、actions、clues、evidenceCards、verdictOptions、reflection、learningPoint、references。actions 與 verdictOptions 的 id 和選項文字六案共用、只存一份，情境資料只放各選項的結果句與 scoreDelta。messageSegments 每段帶 id 與文字，clues 以 segmentId 指向片段、以 kind 區分要查與不用查的句子，點擊區由資料生成；選項中的 scoreDelta 由共用計分函式讀取。未來加入關卡只增加情境資料，通用畫面與狀態機不用複製。

執行狀態包含 scenarioId、phase、initialBelief、actionId、已開啟線索 ID、已閱讀證據 ID、是否已對照（D 是否出現）、selectedEvidenceId、verdictId、finalBelief。所有前進門檻集中判斷。遊戲內返回鍵與瀏覽器返回（含 Android 返回鍵、iPhone 右滑）效果相同：任何階段都回上一階段，保留輸入、可以改答案，分數跟著重算。MESSAGE 階段不顯示遊戲內返回鍵，按瀏覽器返回照常離開頁面。用 sessionStorage 保存同一分頁的本次進度，刷新可恢復，重玩清除；不承諾新分頁一定從零開始，因瀏覽器可能複製開啟者的初始儲存內容。

訊息、線索與卡片文字以安全的 DOM 文字節點呈現；外部來源連結獨立建立。每次切換畫面回到頁首並將焦點放到新標題。只使用單一頁面捲動；底部主要按鈕加 safe-area padding，避免 iPhone Safari 工具列遮擋。點擊區至少 44×44 px，正文維持手機可讀大小；滑桿有大觸控區、即時數值與鍵盤操作。動畫輕量，尊重 prefers-reduced-motion；不用 hover 作為唯一提示。

## 四、實作順序與驗收

1. 將原 index.html 移到 `2026-spring/index.html` 作為 2026 年春季班版獨立入口；新版寫在首頁，更新頁面標題、社群摘要與 README 的入口說明。原始 main 分支不改，所有工作留在 feat/tea-investigation-prototype。
2. 建立情境資料與共用狀態機，再完成訊息、線索、證據卡、結算畫面。保持原版視覺 DNA，採「調查案卷夾住訊息卡」的單一方向。
3. 照「文案規則」請一位 50 歲以上的人朗讀全部文案。測試完整路徑與分支：五種首選行動、線索不足、點到不用查的句子、證據未讀足兩張、沒按對照時不出現 D、選不同證據、三種最終判斷、看完結果返回改答案、刷新恢復、重玩清空。確認分數為純重算。
4. 檢查 320／375／430 px 手機與桌面寬度；長訊息、滑桿、點擊熱區、底部工具列、無橫向／巢狀捲動。以實機覆核觸控與視窗安全區：iPhone Safari、Android Chrome，以及 iOS／Android 的 LINE 內建瀏覽器；遊戲內返回、系統返回與刷新恢復在這幾個環境各測一次。也檢查鍵盤焦點、減少動態效果及來源連結。
5. 完成後整理 README，說明資料欄位與新增第 2–6 關的步驟。請多個獨立視角的 agent 做對抗審查；發現需指向檔案行號與可搜尋原文。修正並驗收後，再依使用者要求準備合併 main。
